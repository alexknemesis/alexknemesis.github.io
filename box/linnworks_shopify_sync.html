Project Brief

Linnworks → Shopify
Barcode Sync

A tool that reads barcodes from Linnworks and writes them into the correct Shopify product variants, automatically.

switch view

The problem

You have barcodes in one system. They need to be in another. How do you move them without doing it manually one by one?

Think of it like a mail sorter. Linnworks has a list of product codes and their barcodes. Shopify has the same products but is missing those barcodes. The tool reads from the first list and fills in the gaps in the second. Once it's built, it does this automatically in seconds, no matter how many products there are.

Two ways to do it

🤖

Option A: Let an AI assistant do it live

You tell an AI agent what to do in plain English and it makes changes directly in your Shopify store, in real time.

No undo if it goes wrong Can't run again easily You have to feed it the Linnworks data manually
⚙️

Option B: Build a small automated script

A small program that connects to both Linnworks and Shopify on its own, reads the barcodes, and writes them in. You run it with one command.

Logs everything it does Safe to rerun anytime Anyone can run it Skips products already done

Recommendation

Build the script. Run it when needed.

Option B takes a few hours to build once, but then it works forever. New products added? Run it again. Barcodes corrected? Run it again. No risk, no manual work.

How it works, step by step

📋
Step 1: Read Linnworks The script logs into Linnworks and pulls a list of every SKU with its barcode.
🔍
Step 2: Find it in Shopify For each SKU, it searches Shopify for the matching product variant.
✏️
Step 3: Write the barcode If found, it saves the barcode to that variant. If not found, it just logs a note and moves on.
📄
Step 4: Show a summary When it's done, it prints how many were updated, how many were skipped, and if anything went wrong.

How to run it

One command in the terminal:

node barcode-sync.js

That's it. The script does the rest.

Want to preview without making changes?

node barcode-sync.js --dry-run

Shows you what it would do, touches nothing.

When to run it again

New products added Run the script. It automatically skips anything already synced.
Barcodes corrected Run it again. It overwrites old values with the new ones.
Big product import Run it after the import is done.
On a schedule It can be set to run automatically every week or month.

Scope

What the project does

Reads barcode values from Linnworks (keyed by SKU) and writes them into the matching product variants on Shopify via productVariantUpdate GraphQL mutation. Designed to be idempotent and reusable across future product additions.

Approach A

Shopify AI Toolkit (interactive agent)

Not recommended for this

Connects an AI agent (Claude Code, Cursor, etc.) to the Shopify platform via MCP/plugin. The agent generates and executes GraphQL mutations against the live store through natural language prompts.

Pros

  • No boilerplate to write for Shopify side
  • Agent has live access to correct API schemas
  • Useful for ad-hoc one-off fixes
  • Accelerates development of the actual script

Cons

  • No native Linnworks integration. Data must be fed manually
  • No draft mode, no preview, no rollback. Mutations are immediate
  • Not reliably repeatable. Each session is stateless
  • Unsafe at scale. Misinterpretation = live store damage before detection
  • Not a reusable tool. Cannot be scheduled or handed off
  • Telemetry: prompts and queries sent to Shopify servers by default

Approach B

Standalone script

Recommended

A Node.js (or Python) script that authenticates with both APIs, loops through Linnworks SKUs, queries Shopify for matching variants, and executes productVariantUpdate mutations. Idempotent: skips variants that already have a barcode set.

Pros

  • Fully automated end-to-end, no manual steps post-setup
  • Idempotent: safe to rerun at any time without side effects
  • Produces a full execution log per run
  • Dry-run mode available (reads and logs, no writes)
  • Testable against a Shopify dev store before production
  • Runnable by non-technical operators after setup
  • Schedulable via cron or task scheduler

Cons

  • Upfront development time (a few hours with AI assistance)
  • One-time credential setup required
  • Needs updating if either API introduces breaking changes

Where the AI Toolkit still helps

Even with Approach B, the Toolkit accelerates the build. With Claude Code + Shopify plugin, the agent generates correct GraphQL mutations and pagination patterns on the first pass because it has live schema access. Without it, an AI assistant guesses at field names and often fails silently. The Toolkit is the build accelerator, not the execution engine.

Execution flow

// Loop logic (pseudo) linnworks.getInventoryItems() → [{ sku, barcode }, ...] for each item: variant = shopify.findVariantBySKU(item.sku) if !variant → log("SKU not found") → continue if variant.barcode === item.barcode → log("skip") → continue shopify.productVariantUpdate(variant.id, { barcode: item.barcode }) log("updated")

When to rerun

TriggerAction
New products added to LinnworksRun the script. Already-synced variants are skipped automatically.
Barcodes corrected in LinnworksRun the script. It overwrites stale values with the new ones.
Bulk product importRun after import is complete.
Scheduled syncSet up cron/task scheduler to run weekly or monthly.

Credentials (one-time setup)

Shopify

Admin API access token with write_products scope. Generate in Shopify Admin under Apps > Develop apps.

Linnworks

Application ID + Secret + session token. Obtained from the Linnworks developer portal. Stored locally in a .env file, never committed to the codebase.
